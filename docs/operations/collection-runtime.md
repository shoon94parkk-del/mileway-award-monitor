# 전체 수집 소요 시간과 병렬 실행 근거

확인일: 2026-11-14 UTC. 아래 시간은 GitHub Actions 실행·단계 메타데이터와 성공 실행의 공개 UI 로그에서 측정했다. 새 항공사 조회 없이 기존 기록만 분석했다.

## 정상 응답일 때의 예상

| 범위 | 기존 구조 실제 측정 | 기존 구조 운영 예상 | 단일 사전 조회 추가 후 계획치 |
|---|---:|---:|---:|
| ICN 출발 33개 노선 | 10분 17초 | 약 10–15분 | **약 11–17분** |
| 유럽 → ICN 14개 노선 | 6분 6초 | 약 6–10분 | **약 7–12분** |
| 위 두 수집을 연속 실행 | 약 16분 23초의 합계 | 약 16–25분 | **약 18–29분** |

운영 예상은 정상적인 GitHub 러너 배정, 의존성 설치, UI 조회, 결과 병합·검증·Git 발행을 포함한 계획치다. 새 구조는 방향별로 Windows 사전 조회 작업 하나를 먼저 실행하므로, 러너 준비·설치·UI 확인에 **약 1–2분씩 추가**한다고 가정했다. 이 추가 시간과 새 구조의 전체 성공 시간은 아직 실측하지 않았다. GitHub 대기열이 길거나 항공사 응답이 느리면 더 걸리며, 실행 시각을 보장하는 상한은 아니다. 두 수집의 일일 예약 시각은 서로 다르므로 위 합계는 연속으로 시작했을 때의 작업 시간이다.

현재 웹은 캐시 방지 쿼리를 붙여 GitHub의 최신 공개 JSON을 읽는다. 데이터 갱신 자체가 Render 재배포 완료를 기다리는 구조는 아니다. 코드 배포 완료와 실제 원천 데이터의 갱신 여부는 별도로 확인해야 한다.

## 실제 몇 대가 동시에 조회했는가

각 worker는 GitHub가 작업 동안 제공하는 **Windows 가상 머신 1대 + 브라우저 1개**다. 상시 운영 서버 5대라는 뜻은 아니다. 한 worker 안에서는 노선과 월을 순서대로 조회한다.

| 수집 | worker별 노선 수 | 한 실행의 브라우저 worker 상한 |
|---|---|---:|
| ICN 출발 | 7 / 7 / 7 / 7 / 5 | 5 |
| 유럽 귀국 | 3 / 3 / 3 / 3 / 2 | 5 |

**현재 코드의 두 workflow는 같은 `public-daily-collection` concurrency group과 `cancel-in-progress: false`를 사용한다.** 출발·귀국 수집이 겹치지 않으며, 먼저 브라우저 1대로 ICN→LHR 한 달의 공식 화면 조회를 확인한다. 이 작업이 성공하고 종료된 뒤에만 5개 worker를 시작한다. 따라서 사전 조회와 본 수집을 합쳐도 **두 방향 전체의 동시 브라우저 상한은 5대**다. 거절되면 5개 worker를 시작하지 않는다. 이 문장은 현재 workflow의 코드 구조를 확인한 결과이며 새 구조의 성공 실행을 관측했다는 뜻은 아니다.

성공 당시에는 두 workflow가 서로 다른 concurrency group을 사용했기 때문에 겹쳐 실행하면 설정상 최대 10대까지 가능했다. 아래 관측은 각 방향의 별도 성공 실행이며 두 방향의 동시 실행을 관측했다는 뜻은 아니다. 사전 검사·병합·상태 기록용 Linux 작업은 항공사 달력을 조회하는 브라우저 worker 수에 포함하지 않았다.

- 출발편의 5개 작업은 모두 **00:15:46 UTC**에 시작했다. 실제 조회 단계도 **00:16:11–00:23:01 UTC** 동안 다섯 개가 겹쳤다.
- 귀국편은 작업들이 **00:58:21–22 UTC**에 시작했고, 실제 조회 단계가 **00:58:43–01:01:14 UTC** 동안 다섯 개 겹쳤다.

- 전체 실행: **00:15:43 → 00:26:00**, 10분 17초.
- 마지막 worker 종료: 00:25:34. 병합·발행 작업: 00:25:37 → 00:25:47.
- 실제 데이터 Git 발행 단계: **00:25:42 → 00:25:44**, 발행 커밋 `86ff6da`.

## 성공 기록: 유럽 귀국

[실행 43131169068](https://github.com/shoon94parkk-del/mileway-award-monitor/actions/runs/43131169068), 코드 `0a91261`, 2026-11-12 UTC.

- 전체 실행: **00:58:18 → 01:04:24**, 6분 6초.
- 최장 조회 worker: IST/ZRH/CDG, **00:58:37 → 01:04:06**, 5분 29초.
- 나머지 조회 단계: 2분 34초 / 3분 50초 / 3분 53초 / 5분 3초.
- 병합·발행 작업: 01:04:13 → 01:04:23. 데이터 발행 단계: **01:04:18 → 01:04:20**, 커밋 `929fbd6`.
- **14 × 13 = 182개 노선·월 단위**, **172개 COVERED + 10개 UNQUERYABLE**, 실패 0개.

`UNQUERYABLE`은 공식 화면이 해당 여정을 조회할 수 없다고 응답한 경우다. 위 수치는 검색 처리 범위이며 좌석이 있는 날짜 수나 잔여 좌석 수가 아니다. 모든 단위를 처리한 `attempt_complete=true`와 모든 단위에 달력이 존재하는 `complete=true`는 다르다. 이 두 성공 기록은 공식 UNQUERYABLE 때문에 `complete=false`를 유지하면서 전체 시도를 완료했다.

## 실제 병목

연속 월 결과 로그 사이의 중앙값은 출발편 **3.94초**, 귀국편 **4.45초**였다. 설정된 월별 간격 3초 / 3.5초에 UI 렌더링·읽기 시간이 더해진다. 노선을 바꿀 때는 초기 화면과 출도착 선택을 다시 확인하므로 중앙값 **23.2초 / 22.74초**가 들었다.

출발편은 ZRH/EWR/MEL에서 첫 시도 월 불일치가 한 번씩 발생한 뒤 재시도로 복구했다. 귀국편은 ZRH 재시도와 BCN/ZRH의 UNQUERYABLE 이후 화면 재초기화가 오래 걸렸다. 마지막 귀국 worker의 일반 노선은 월 결과 13개 사이에 약 53초가 들었지만, ZRH는 약 158초였다. 단순히 전체 단위를 5로 나누는 계산보다 가장 느린 worker와 재초기화·재시도가 전체 시간을 잘 설명한다.

## 접근 제한 중에는 완료 시각을 예측할 수 없음

2026-11-14의 [실행 43546142771](https://github.com/shoon94parkk-del/mileway-award-monitor/actions/runs/43546142771)에서도 공식 공개 조회가 다시 **HTTP 403**을 반환했다. 위 정상 소요 시간은 항공사가 달력을 제공할 때만 적용된다. 거절 상태가 언제 해제될지는 현재 증거로 알 수 없으므로 **전체 검색·신규 발행의 유한한 완료 ETA를 제시할 수 없다**.

명시적 403/429를 관측하면 조회를 중단하고 마지막 정상 데이터를 유지한다. 관측 시점부터 60분간 브라우저 실행을 제한한다. 매시 17분의 복구 스케줄만으로 계산하면 다음 시도는 거절 관측 후 약 **60–120분 + GitHub 예약 지연·대기열**에 가능하지만, 이는 다음 시도 시각이지 완료 시각이 아니다. 다시 거절되면 성공적인 수집·발행 없이 제한 상태가 이어진다.

[실행 43540577826](https://github.com/shoon94parkk-del/mileway-award-monitor/actions/runs/43540577826)은 이 제한 검사 때문에 5개 브라우저 worker와 발행을 모두 건너뛰었고, 상태 기록까지 약 **40초** 만에 끝났다. 짧게 끝난 workflow가 전체 검색을 완료했다는 뜻은 아니다. 현재 데이터와 항공사 원천 시각, 수집 성공, 발행 성공은 각각 따로 확인해야 한다.

## 확인 방법

- GitHub REST: `actions/runs/{run_id}` 및 `actions/runs/{run_id}/jobs`의 `created_at`, `started_at`, `completed_at`와 단계별 시각.
- 성공 실행의 로그 ZIP에 있는 `OUTBOUND UI`, `RETURN UI ONLY`, `ACCELERATION`, `RETURN UI COMPLETE` 결과 줄.
- 공개 파일: `public-data/snapshot.json`의 `bootstrap.report`, `public-data/returns.json`의 coverage/unqueryable 및 처리 완료 상태.
- 현재 병렬 수와 제한 설정: `.github/workflows/collect.yml`, `.github/workflows/collect-europe-returns.yml`, `.github/workflows/recover-access-limit.yml`.

공개 결과·상태·작업 시간만 분석했다. 자격 증명, 사용자 알림 규칙, 항공사 응답 본문은 이 문서에 포함하지 않았다.
